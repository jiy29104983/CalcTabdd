# CalcTabdd

notepad-- 的标签页计算器插件，使用 C++14 / Qt 5.15。名称中的 `dd` 表示 `--`。
当前版本 **0.2.0 测试版**，采用“公式在上、结果在下”的连续计算记录布局。

## 使用

1. 将测试包中的 `plugin/calctabdd.dll` 放入 notepad-- 安装目录的 `plugin` 文件夹。
2. 重启 notepad--，选择 **插件 → CalcTabdd 计算器 → 打开计算器**。
3. 在底部输入公式，点击“计算”或按 **Ctrl+Enter**；普通 Enter 不提交。
4. 上方按顺序显示公式和结果。“再次使用 / 修改公式”可将原公式放回输入区；结果可选中复制。

每个宿主窗口拥有独立计算器。重复打开会回到已有标签；关闭标签后清空其记录，重开为新的
计算会话。当前不进行跨启动历史保存。用户已于 2026-10-03 确认 EVO-001 实机验收完成，
反馈来源与环境记录边界见[手动测试与验收记录](docs/manual-testing.md#验收记录)。

## 帮助、快捷补全与关于

- 点击计算器右上角的 **帮助**，或选择 **插件 → CalcTabdd 计算器 → 运算与精度帮助**。
  帮助窗口可保持打开，支持英文名称与中文关键词搜索；“运算速查”列出全部运算和参数示例，
  “精度与限制”解释显示位数、整数边界、舍入、溢出／下溢和常见疑问。
- 在公式需要函数或常量的位置输入 `@`，列出 14 个函数与 `pi`、`e`、`ans`。
  例如 `@sq`／`@平方根` 查找 `sqrt`，`@对数` 查找 `ln`／`log`，`@上次` 查找 `ans`。
  使用 ↑↓ 选择、Enter 或 Tab 插入、Esc 关闭，也可点击候选。`/` 继续作为除号。
- 选择后仅替换当前 `@关键词`，保留公式前后内容。`2+@sq` 会变成 `2+sqrt()`，光标进入括号；
  `@pow` 插入 `pow(, )`，光标位于第一个参数处。已有括号和参数不重复插入。补全支持撤销／重做。
- Ctrl+Enter 和计算按钮遇到未完成的 `@` 查询会提示先完成或删除查询，不提交记录。
  输入法组词期间由输入法处理候选，文字上屏后再匹配。候选关闭时普通 Enter 仍不提交。
- **插件 → CalcTabdd 计算器 → 关于 CalcTabdd** 显示插件版本、目标 Windows x64 / Qt 5.15.2 /
  MSVC v142、notepad-- v3.8.3 / v3.9.0 源码兼容参考，以及不同宿主的实机验证边界。

## 计算算法与精度报告

> 算法审查日期：2026-10-02；原审查版本：0.1.0；计算引擎源码基线：`a5fcf5d`。
> 0.2.0 新增帮助与补全，计算算法和精度策略未改变。下表的验证状态保留原审查时点；
> 新版构建与测试结果见 [0.2.0 验证记录](docs/verification-v0.2.0.md)。
> 依据：[表达式引擎](src/expression_engine.cpp)、[结果类型](src/expression_engine.h)、
> [计算页面](src/calculator_page.cpp)、[引擎测试](tests/engine_tests.cpp)和[页面测试](tests/page_tests.cpp)。
> 下文区分源码确认、独立数值探针与插件运行验证；本次没有完成 Windows 插件精度验收。

**结论：当前是双精度实数表达式计算器，实现了递归下降解析、6 种二元运算符、
一元正负号和 14 个内置函数。内部用 `double` 计算，结果显示最多 15 位有效数字；
这不表示所有公式都能保证 15 位准确数字。** 常规数值计算可用，但大整数、小数精确计算、
接近奇点或存在严重消去误差的公式需要特别注意。

### 1. 已实现的算法与语法

解析器在扫描输入时直接求值，调用层次为
`expression → term → unary → power → primary`，分别处理加减、乘除取余、一元符号、
乘方和数字／常量／括号／函数。没有单独构建抽象语法树，也没有符号化简或精确分数运算。

| 类别 | 支持的写法 | 实际实现与规则 |
| --- | --- | --- |
| 加减乘除 | `+ - * /` | 使用 C++ `double` 四则运算；加减低于乘除；同级从左向右，`8/4/2 = 1` |
| 浮点取余 | `%` | 调用 `std::fmod`，与乘除同级；余数可带小数，非零余数与被除数同号，如 `5.5%2 = 1.5`、`-10%3 = -1`；不是百分比，也不是总为非负的模运算 |
| 乘方 | `^`、`pow(x,y)` | 调用 `std::pow`；`^` 右结合，`2^3^2 = 512`；`pow` 必须有两个参数 |
| 一元符号与括号 | `+x`、`-x`、`(…)` | 支持连续符号和括号；乘方优先于一元负号，`-2^2 = -4`、`(-2)^2 = 4`、`2^-3 = 0.125` |
| 平方根、绝对值 | `sqrt(x)`、`abs(x)` | 调用 `std::sqrt`、`std::abs`；仅支持实数结果 |
| 三角函数 | `sin(x)`、`cos(x)`、`tan(x)` | 调用对应的 C++ 标准数学函数；参数使用弧度，没有角度模式 |
| 对数、指数 | `ln(x)`、`log(x)`、`exp(x)` | 分别调用 `std::log`、`std::log10`、`std::exp`；`ln` 是自然对数，`log` 是以 10 为底的对数 |
| 整数舍入 | `floor(x)`、`ceil(x)`、`round(x)` | 分别向下、向上、向最近整数舍入；`round` 遇到恰好半整数时远离 0，`round(1.5) = 2`、`round(-1.5) = -2`，不是银行家舍入 |
| 二元比较 | `min(x,y)`、`max(x,y)` | 使用 `qMin`、`qMax` 选择两个已求值参数；不支持三个或更多参数 |
| 常量 | `pi`、`e` | 分别由 `std::acos(-1.0)`、`std::exp(1.0)` 生成双精度近似值，没有额外高精度常量库 |
| 连续计算 | `ans` | 引用上一次成功计算的内部 `double` 值；初始为 0，失败不更新，关闭标签后重置 |

14 个内置函数为：`sqrt`、`abs`、`sin`、`cos`、`tan`、`ln`、`log`、`exp`、
`floor`、`ceil`、`round`、`min`、`max`、`pow`。除最后三个接受两个参数外，均接受一个参数。
这些函数使用 Qt／C++ 标准库；仓库没有自行实现泰勒展开、CORDIC、牛顿迭代等底层数学算法，
不能据此认定所链接标准库内部采用了哪一种近似方法。

输入还支持以下规则：

- 十进制整数、小数（包括 `.5`、`1.`）和科学计数法，例如 `1e3`、`2.5E-2`。
  字面量通过 `QLocale::c().toDouble` 转为 `double`，小数点固定为 `.`，不接受千分位分隔符。
- 函数和常量不区分大小写，可嵌套调用；空白字符会被跳过。
  `×`、`÷`、`−` 自动转换为 `*`、`/`、`-`。
- 乘法必须显式写出，`2*pi` 合法，`2pi`、`2(3)` 不合法。
- 输入长度上限为 4096 个 `QString` UTF-16 代码单元；递归深度计数上限为 128，
  计数涉及括号、函数参数、一元符号和幂链，并不等同于可嵌套 128 对括号。

当前没有实现任意精度整数／小数、十进制定点计算、复数、符号求解、方程求根、
微积分、矩阵、统计聚合、阶乘、进制转换或自定义变量赋值。

### 2. 计算精度与显示精度

数值输入、中间结果、函数参数、返回值和 `ans` 都使用 `double`。下表按 IEEE 754
**binary64** 说明；本次独立探针确认本机 `double` 为该格式。源码没有使用 `long double`
或任意精度库，也没有实现补偿求和、误差估计或精确十进制运算。

| 项目 | 数值／行为 | 含义 |
| --- | --- | --- |
| 存储与有效位 | 64 位存储、53 位二进制有效精度 | 通常约 15～16 位十进制有效数字；不等于 15～16 位小数，也不是任意公式的准确位数保证 |
| 1 附近的相邻数间距 | `2^-52 ≈ 2.2204460492503131e-16` | 即 `double` 的 epsilon；数值越大，绝对间距通常越大，不能把 epsilon 当成所有结果的绝对误差上限 |
| 连续整数精确表示范围 | `[-2^53, 2^53]`，即 `±9007199254740992` | 范围内每个整数都可精确表示；超出后只有部分整数可表示。表达式是否精确还取决于中间运算 |
| 最大有限值 | 约 `1.7976931348623157e308` | 运算得到无穷大时报告溢出 |
| 最小正正规数 | 约 `2.2250738585072014e-308` | 更小的非零值进入非正规数区域，有效精度逐渐下降 |
| 最小正非正规数 | 约 `4.9406564584124654e-324` | 默认支持渐进下溢时的表示边界；结果过小可能舍入成 0，本引擎不另报下溢 |
| 结果显示 | `QString::number(value, 'g', 15)` | 最多 15 位有效数字，可能采用科学计数法；显示时把负零统一为 `0` |
| 结果复用 | `ans` 保存 `result.value` | 后续计算不经过显示字符串转换；复制显示结果再输入，可能损失内部保留的数字 |

**显示舍入不会提高内部计算精度。** 例如 `0.1+0.2` 显示为 `0.3`，
源码中已有该显示断言；其内部值仍可能为 `0.30000000000000004`。
完整往返保存任意 binary64 数值通常需要最多 17 位有效数字，当前 15 位显示不具备这一保证。
即使一个大整数在内部可精确表示，其显示文本也可能被舍入。

`ans` 的差别可用 `1/3` 说明：其 15 位显示文本为 `0.333333333333333`。
本次数值探针中，保留内部值再乘 3 得到 `1`；把这段显示文本重新当成数字乘 3，
得到约 `0.9999999999999989`。页面源码确认 `ans` 使用前一种路径，
但这组连续操作本次未在 Qt 页面中运行。

### 3. 精度边界的数值观测

以下结果来自 **Linux x86_64、GCC 13.3.0、glibc 2.39、C++14** 的独立数值探针，
使用与引擎相同的 `double` 运算和 `std::` 数学函数，按 17 位有效数字输出内部值。
探针确认了 binary64 和当前“舍入到最近值”模式。
**探针没有调用 `ExpressionEngine::evaluate`，也没有运行 Qt 格式化或 Windows DLL；
这些结果用于解释数值层行为，不是插件端到端实测，标准数学函数的末尾数字可能因平台而异。**

| 公式／对应数值运算 | 本次数值层观测 | 精度含义 |
| --- | --- | --- |
| `0.1+0.2` | `0.30000000000000004` | 常见十进制小数不能用有限二进制位精确表示 |
| `0.1+0.2-0.3` | `5.5511151231257827e-17` | 显示为简洁小数并不表示后续运算没有残差 |
| `(9007199254740992+1)-9007199254740992` | `0`，数学值为 `1` | 在 `2^53` 附近，增加 1 可能被舍去 |
| `(1e16+1)-1e16` | `0`，数学值为 `1` | 大小数相加丢失低位，再相减无法恢复 |
| `(1e16-1e16)+1` 与 `1e16+(-1e16+1)` | 分别为 `1` 和 `0` | 浮点加法不满足实数意义上的结合律 |
| `sqrt(2)^2-2` | `4.4408920985006262e-16` | 平方根和幂运算后的结果不一定精确抵消 |
| `sin(pi)` | `1.2246467991473532e-16` | `pi` 是近似值，引擎不会把接近 0 的值自动归零 |
| `tan(pi/2)` | `16331239353195370`，有限值 | 真正的数学奇点没有专门识别；近似输入可返回很大的有限结果 |
| `0.3%0.1` | `0.099999999999999978` | 二进制小数的浮点取余可能明显不同于十进制精确取余的 `0` |
| `round(1.005*100)/100` | `1` | 先转为二进制浮点再缩放，可能跨过预期十进制舍入边界；不是精确的“保留两位小数”算法 |
| `1e-200*1e-200`、`exp(-1000)` | 均为 `0` | 运算下溢可静默归零 |
| `pow(-8,1/3)` | `NaN` | 浮点分数指数调用 `std::pow`，不会识别成实数立方根 `-2`；引擎据此报告定义域错误 |

另以 Python `Decimal` 的 **80 位有效数字参考值**比较了三个常规函数样本。
误差按探针结果恢复出的精确 binary64 值计算，没有使用 15 位显示文本。

| 样本 | 内部结果（17 位诊断输出） | 对参考值的绝对误差（约） | 相对误差（约） |
| --- | --- | --- | --- |
| `sqrt(2)` | `1.4142135623730951` | `9.6673e-17` | `6.8358e-17` |
| `ln(2)` | `0.69314718055994529` | `2.3190e-17` | `3.3457e-17` |
| `exp(1)` | `2.7182818284590451` | `1.4456e-16` | `5.3182e-17` |

这三个样本体现了常规输入下约 `1e-16` 量级的相对误差；**不能外推成全部函数、
全部输入或复合公式的误差保证**。接近零点／奇点、相近数相减、巨大三角函数参数、
多步连续计算等情况，需要单独评估。

### 4. 错误检测及未覆盖的数值风险

| 情况 | 当前处理 |
| --- | --- |
| `/`、`%` 的除数恰好为 0（包括负零） | 明确拒绝；使用 `divisor == 0`，没有“接近 0”阈值 |
| 数学函数返回 `NaN`，例如 `sqrt(-1)`、负底数的非整数次幂 | 报告“运算超出实数定义域” |
| 中间运算或函数返回正／负无穷大 | 报告“数值溢出”；例如 `1e308*2`、`2^1024` |
| `ln(0)`／`log(0)` | 标准数学函数返回负无穷大时，被统一归为“数值溢出”；当前没有专门的对数定义域提示 |
| 数字字面量转换失败 | 报告“数值超出支持范围”；与运算过程中的下溢处理不同 |
| 非法语法、未知名称、参数个数错误、长度／递归限制 | 返回错误信息与位置；页面保留输入供修改，成功结果历史和 `ans` 不被失败结果替换 |
| 有限但不可靠的结果 | 不检测有效数字损失、严重消去误差、函数病态输入或数学奇点附近的有限值 |
| 运算下溢或非正规数精度损失 | 仅检查 `NaN`／非有限值，没有检查 `errno` 或浮点异常标志；有限值或 0 会被接受 |

引擎逐步检查中间结果，不能指望后续运算“救回”溢出，例如 `(1e308*2)/2`
会在乘法阶段失败。目标宿主若改变浮点舍入或非正规数处理模式，引擎也没有主动设置或恢复这些模式；
上面的本机观测不构成对所有宿主浮点环境的保证。

### 5. 原算法审查的验证情况与使用结论

原审查时的 `engine_tests` 源码包含 **37 条正常计算数据、26 条错误输入数据**，另有一个
显示／区域设置测试槽；页面测试还检查失败保留输入和 `ans`。这些数量不包含 QtTest
自动生成的初始化／清理项，也不等于本次通过数量。
正常计算断言使用：

```text
abs(actual - expected) <= 1e-12 * max(1, abs(expected))
```

当参考值绝对值不超过 1 时，这是 `1e-12` 的绝对误差容忍；更大时约为 `1e-12`
的相对误差容忍。该阈值比 binary64 的常规舍入误差宽松，不能证明结果有 15 位准确数字。
现有测试也没有给出全输入域的 ULP（相邻浮点数间距）误差上限或完整的高精度参考对照。

**适用性：**日常算式、比例换算和允许浮点近似的实数计算符合当前能力；要求十进制精确舍入、

这些是改进方向，本报告没有修改计算算法或精度策略。

## 宿主集成与兼容性

目标构建环境为 **Windows x64、Qt 5.15.2、MSVC v142**。公开 notepad-- 源码基线为
`91105f68b74382128f3313ac5af8accdc77de918`。本地 `v3.8.3` / `v3.9.0` 标签指向同一
源码提交，但不意味着两版发布二进制相同。用户已确认当前功能实机验收完成，
该反馈不外推为两个宿主版本或未来构建都已验证；具体记录见[手动测试](docs/manual-testing.md#验收记录)。

插件让宿主创建并登记原生文本标签，保留原生 QScintilla 对象，在内部嵌入计算器页面，
不直接将普通 QWidget 插入宿主标签容器。底层空白文档设为只读并隔离输入事件。

计算器激活时，宿主菜单中的复制、粘贴、剪切、全选、撤销、重做转向计算器；保存、另存为、
查找替换等文本文件命令临时不可用。切回普通文档后恢复原操作。关闭、切换标签继续由宿主管理。

## 构建与测试

安装 Qt 5.15 开发包和 CMake 后：

```bash
cmake -S . -B build/local -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DCMAKE_PREFIX_PATH=/path/to/Qt \
  -DCALCTABDD_HOST_SOURCE_DIR=/path/to/notepad--
cmake --build build/local --parallel 4
ctest --test-dir build/local --output-on-failure --no-tests=error
```

没有指定宿主源码时仅运行引擎和页面测试，不包含原生控件集成测试。提供已编译的宿主
QScintilla 静态库时，可通过 `CALCTABDD_QSCINTILLA_LIBRARY` 指定；否则从固定宿主源码
构建测试依赖。正式插件仅依赖 Qt Core / Gui / Widgets，不依赖另一个 QScintilla DLL。

GitHub Windows 流水线在 `main` 推送、PR 和手动触发时编译 Release 并执行三个测试套件，
通过后打包 DLL、中文安装说明、手测清单、变更说明、许可证和构建信息。主分支成功构建
额外发布带提交号的**预发布测试包**，供手动验收，不标记为稳定正式版本。
