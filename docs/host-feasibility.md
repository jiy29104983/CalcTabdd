## 产品目标与结论

CalcTabdd 计划集成到 notepad-- 的新标签页：底部输入计算公式，确认后在上方按顺序
列出公式与结果。提交方式可采用 Ctrl+Enter，不要求只能用普通 Enter。

具备开发原型的条件。优先路线是调用宿主新建原生文本标签页，保留宿主依赖的原生
编辑器对象，再在其内部嵌入铺满页面的计算器界面。公式求值和历史记录由插件管理。

当前公开源码没有完整的自定义 QWidget 标签页注册接口；直接向标签容器插入普通
QWidget 存在具体的关闭路径空指针风险。隔离控件验证通过不代表完整宿主支持已经验收。

## 建议接入方案

1. 用户从插件菜单打开计算器。
2. 插件通过宿主回调创建正常的文本标签页，保留原生编辑器作为标签根对象。
3. 插件在该编辑器内部创建计算器界面，跟随页面尺寸变化，显示为“计算器”标签。
4. 上方历史区显示公式与结果，下方输入区支持确认按钮或 Ctrl+Enter。
5. 每个宿主窗口管理自己的页面与状态；页面跟随所属原生编辑器销毁。
6. 计算引擎和历史模型独立于隐藏的文本缓冲区。

这是优先验证的兼容方案，并非正式宿主提供的自定义标签 API。正式实现必须处理
菜单命令、应用快捷键、关闭和退出，不能只验证页面能显示。

## 隔离验证中的发现

Qt 控件探针在真实 QScintilla 控件中嵌入页面，验证了布局、输入焦点、标签切换、
窗口状态隔离及父子销毁。主程序链接宿主配套 QScintilla 静态库，动态模块只使用公共 Qt 接口。

最初的 Enter 方案中，输入框处理提交后，未消费的按键继续向父控件传播，造成隐藏的
文本编辑器发生变化。在嵌入页面接收未处理的 keyPress/keyRelease 后，Enter 方案
16/16 通过。后续 Ctrl+Enter 方案 19/19 通过，普通 Enter 不提交，也不修改底层文本。

这些检查只追加输入记录，没有计算公式；未启动完整 CCNotePad，也未验证其自身的
关闭函数、宿主菜单或 Windows DLL。具体检查及证据边界见[验证记录](verification-2026-10-01.md)。

## 后续开发前需要验证与决定的事项

1. 最小 Windows DLL 能加载，能反复打开计算器标签并切回普通文档。
2. 关闭当前、关闭其他、关闭左右、关闭全部、退出、取消退出和恢复会话的行为。
3. Ctrl+S、另存为、查找替换、撤销，以及宿主菜单复制粘贴应如何路由。
4. 两个宿主窗口的数据隔离、中文输入法、主题切换和 DPI。
5. 是否需要重启后保留历史；若需要，由插件独立保存并明确恢复规则。
6. 支持的运算、函数、数值精度、错误提示和历史操作属于后续产品需求，尚未确定。

优先完成标签接入与生命周期验证，再实现计算引擎和历史持久化。
